# YES or NO

목적은 사용자의 의사결정을 끝까지 수행하고, 현재 확인된 근거에서 가장 나은 권고를 완성된 보고서로 제공하는 것입니다. JEV는 의견의 타당성과 실행 가능성을 평가하고 재판정합니다. 최종 보고서는 자료 나열이나 “종합적으로 알아서 판단하라”는 결론으로 끝내지 않습니다.

Windows Electron 의사결정 앱입니다. 첫 질문에는 바로 결론을 내리지 않습니다. 사용 가능한 Claude Code·ChatGPT(Codex)·Gemini가 조사 계획과 사전 질문을 제안하고 TypeSafe JEV가 필요한 자료를 분류합니다. 질문과 자료가 충분히 명확하면 공개 자료 조사를 자동으로 시작하며, 추가 확인이 필요할 때만 사용자에게 질문이나 자료를 요청합니다. 사전 확인 후 공개 자료를 실제 검색·수집한 뒤, Claude와 Codex의 각 3인 토론 → JEV 중간 판정 → 각 AI의 독립 재검증 → JEV 재평가 → 최종 실행안을 진행합니다. 새 최종 판정은 YES / NO / 조건부 권고이며, 근거·가정·조건을 함께 제공합니다.

## Windows 설치와 업데이트

[GitHub Releases](https://github.com/hanbroz/yesornot/releases/latest)에서 `YESORNOT-Setup-버전.exe`를 내려받아 설치합니다. 사용자별 설치이며 기존 `%APPDATA%/YESorNOT` 기록과 암호화 키를 유지합니다. 현재 배포본은 Authenticode 서명이 없어 Windows SmartScreen 경고가 나타날 수 있습니다.

연결 및 평가 설정에서 **JEV API 키**와 **Gemini API 키**를 입력하고 **API 키 저장**을 누릅니다. 빈 입력란은 기존 키를 유지하며, 저장된 키는 다시 표시하지 않습니다. 키는 Windows 사용자 계정에 연결된 암호화 저장소 파일에 보관하고, 암호화 저장이 불가능하면 저장을 거절합니다. 설정 화면에서 저장한 키가 개발용 `.env`보다 우선합니다. Claude Code와 Codex는 별도로 공식 CLI를 설치하고 구독 계정으로 로그인해야 합니다.

설치형 앱은 시작 시와 6시간마다 공개 GitHub 릴리즈를 확인하고 새 안정 버전을 자동 다운로드합니다. 다운로드가 끝나면 앱을 종료할 때 적용하며 **재시작하여 업데이트**로 바로 적용할 수 있습니다. 판단 진행 중에는 재시작 설치를 차단합니다. 업데이트 화면은 연결 설정에 있습니다. 개발 실행과 기존 포터블 빌드는 자동 업데이트 대상이 아닙니다.

공개 릴리즈의 `latest.yml`, 설치 파일과 `.blockmap`이 자동 업데이트에 필요합니다. HTTPS와 SHA-512로 다운로드 무결성을 확인하지만, 현재 서명 없는 배포본은 인증서로 게시자 신원을 검증하지 않습니다. 향후 코드 서명을 도입할 때 기존 설치본의 업데이트 호환성을 함께 검증해야 합니다.

## 로컬 릴리즈 빌드

`npm ci` → `npm run check` → `npm test` → `npm run build:installer` 순서로 실행합니다. Windows x64 설치 파일, 차등 업데이트 파일, `latest.yml`, `SHA256SUMS.txt`가 `dist/`에 생성됩니다. 빌드 명령은 GitHub에 자동 게시하지 않습니다. 버전을 올린 커밋에 태그를 붙이고 같은 버전의 네 파일을 GitHub Releases에 함께 업로드합니다.

공개 커밋 전 `node scripts/check-secrets.cjs`를 실행합니다. 이 검사는 Git에 스테이징한 파일에서 금지 경로, 로컬 API 키와 알려진 자격 증명 형식을 검사합니다. `git config core.hooksPath .githooks`로 커밋 전 검사도 적용할 수 있습니다. `.env`, 키 파일, 판단 이력, `.omx/`, `out/`, `dist/`는 공개 저장소에서 제외합니다. 설치 파일은 실행에 필요한 허용 목록으로 구성하며 압축된 실제 내용에서도 로컬 API 키와 개인 설정 파일이 없는지 빌드 중 검사합니다.

## 실행

- `run.bat`: 소스 검사 → 이 프로젝트의 기존 앱 종료 → 최신 소스·디자인으로 재빌드 → 새 앱을 일반 창으로 실행합니다. 검사·빌드 실패 시 이전 패키지를 실행하지 않습니다.
- 재빌드 없이 실행: `out/YESORNOT-win32-x64/YESORNOT.exe`
- 개발 실행: `npm install` 후 `npm start`
- 검증: `npm test`, `npm run check`
- Windows 포터블 빌드: `npm run package`
- 실제 서비스 호출 검증(구독 사용량과 Jev API 사용량 발생): `npm run smoke:live`

Node.js 24와 공식 Claude Code / Codex CLI를 사용합니다. Claude·ChatGPT는 이 PC의 구독 로그인을 재사용하며, Gemini는 Gemini Developer API를 직접 호출합니다. 로컬 앱을 사용해도 추론은 각 제공사의 클라우드에서 처리됩니다.

Gemini는 Google AI Studio의 Free Tier 프로젝트에서 발급한 키를 `.env`의 `GEMINI_API_KEY`에 설정합니다. 기본 모델은 `gemini-3.5-flash-lite`이며, 선택 변수 `GEMINI_MODEL`로 변경할 수 있습니다. 무료 등급 여부와 실제 할당량은 AI Studio에서 확인해야 합니다. API 키 유효성 확인만으로 무료 등급을 판별할 수 없습니다. 모델 메타데이터로 연결을 확인하며, 이 확인은 의견 생성 요청을 보내지 않습니다. 앱은 결제를 설정하거나 다른 모델·유료 경로로 자동 전환하지 않습니다. 무료 API 입력·출력은 Google의 개선과 검토에 사용될 수 있으므로 기밀·개인정보를 보내지 마세요. [키 발급](https://aistudio.google.com/apikey), [무료 등급](https://ai.google.dev/gemini-api/docs/billing), [데이터 조건](https://ai.google.dev/gemini-api/terms#unpaid-services).

## 사전 질문과 공개 자료 조사

1. **사전 검토(항상):** 사용 가능한 각 AI가 질문의 대상·선택지·목표·제약과 첨부 자료가 충분히 명확한지 먼저 검토하고, 공개 조사 검색어와 필요한 확인 질문을 독립적으로 제안합니다. 뉴스·공식 통계·정책·논문·반대 근거 중 질문에 관련된 자료를 계획하며, 인터넷에서 구할 수 있는 사실 조사를 사용자에게 맡기지 않습니다.
2. **질문 분리·중복 제거와 JEV의 필요성 검토:** 각 AI가 낸 최대 24개 후보를 검토합니다. 한 항목에는 독립적으로 답할 정보 하나만 묻습니다. 자기 자금·월 상환 한도·기한은 각각 다른 질문이며, 이유나 자료 안내에 다른 질문을 숨기지 않습니다. 복합 원본은 여러 단일 질문으로 나누고 같은 정보를 묻는 표현만 합칩니다. 질문 수를 줄이려고 다른 조건을 묶지 않으며, 최대 48개 단일 후보를 지원합니다. 모든 원본과의 연결은 보존합니다. JEV가 복합 질문을 발견하면 LLM이 다시 분리하고 JEV가 재검토합니다(추가 1회). 재검토 후에도 복합 질문이 남으면 해당 질문지를 표시하지 않고 오류를 알립니다.
3. **추가 질문·자료 요청(필요한 경우):** JEV는 가능한 답이 달라졌을 때 조사 방향이나 최종 행동이 실제로 달라지는지, 이미 제공한 내용·공개 조사·합리적 가정이나 시나리오 비교로 대체할 수 없는지 검토합니다. 단순히 있으면 유용하거나 정확도가 높아진다는 이유로 질문하지 않습니다. **새 질문지에는 JEV가 필수로 판단한 항목만 표시**하고, 선택 정보·불필요한 정보·이미 제공한 내용·공개 조사 대상은 질문에서 제외합니다. 필요한 답변과 파일을 추가한 뒤 **답변 반영 · 자료 조사 시작**을 누릅니다. 알 수 없는 항목에는 `모름`이라고 적을 수 있습니다. **추가 확인이 필요 없으면 공개 자료 조사를 자동으로 시작합니다.** 어느 경로든 조사 근거를 확보하기 전에는 토론이나 결론 생성을 시작하지 않습니다.
4. **실제 자료 조사:** 답변을 반영해 공개 검색어를 다시 구성한 뒤 각 AI가 웹 도구로 조사합니다. Claude는 WebSearch·WebFetch, Codex는 live web search, Gemini는 Google Search grounding을 사용합니다. 도구의 실제 실행 기록과 제공된 출처를 수집하고, 앱이 출처 URL에 별도로 접근해 자료를 수집합니다.
5. **근거를 공유한 토론:** 수집된 출처에 `[S1]` 같은 번호를 붙여 토론·JEV 평가·재검증·최종 작성에 전달합니다. 접근·검색이 확인된 최대 30개 출처에 근거 분량을 배분하여 뒤쪽 공식·논문 출처도 포함합니다. 10,000자 공개 근거 예산과 전체 24,000자 제한에 따라 일부 내용을 생략하며, 원문과 미검증 모델 요약을 구분합니다. 자료 수나 종류 충족은 모든 중요한 주장에 충분한 근거가 확보되었다는 뜻이 아닙니다. 화면에서 실제 검색 기록, 출처, 원문 접근 상태와 미확인 항목을 확인할 수 있습니다.

검색 결과만 확인한 자료(`search-result`), 앱이 본문을 수집한 자료(`retrieved`), 접근·검색 근거를 확인하지 못한 자료(`unavailable`)를 구분합니다. **접근 성공은 내용의 진실성이나 전문 전체 검토를 보장하지 않습니다.** 자료의 발행일·지역·품질·상반된 주장과 질문에 대한 적용 가능성은 이후 토론에서도 검토합니다. 모델이 스스로 쓴 URL 목록만으로 실제 조사 완료를 인정하지 않습니다.

조사 계획에 비해 실제 검색어·독립 도메인·필요한 근거 종류가 부족하면 해당 조사 AI가 **최대 1회** 공개 보완 조사를 합니다. 보완 뒤에도 남은 접근 제한·누락·일부 AI의 실패는 `partial`로 표시합니다. 광범위한 계획을 세웠는데 실제 검색이나 확인된 출처가 최소 수준에도 못 미치면 `RESEARCH_INCOMPLETE`로 토론 전에 중단합니다. 실제 검색 또는 확인 가능한 출처가 전혀 없어도 판단을 시작하지 않습니다. 이 범위 검사는 전 세계 자료를 빠짐없이 조사했다는 보증이 아닙니다.

사전 검토 시작을 누르면 질문 입력란 아래에 로딩 표시와 경과 시간이 즉시 나타납니다. AI 사전 검토의 실제 응답 완료 건수, 유사 질문 통합, JEV 사전 평가 등 현재 단계를 표시합니다. 추가 답변을 기다리거나 실행이 완료·실패·취소되면 로딩 표시가 사라집니다.

## 실행 버전과 질문지 파일

- 창 제목과 화면 상단에 `ver. yyyy.MM.dd.HH.mm.ss`를 표시합니다. 한국 시각(Asia/Seoul)의 **빌드 시각**이며, 같은 EXE를 다시 실행해도 바뀌지 않습니다. `run.bat`으로 다시 빌드하면 새 버전이 표시됩니다. 패키지 정보가 없는 개발 실행은 창 제목에 `개발 모드`로 표시합니다.
- 사전 질문에 답변을 기다리는 화면에서 **질문지 다운로드**로 TXT 파일을 저장합니다. 이미 입력한 답변도 포함됩니다. 메모장에서 각 답변 시작·끝 표시 사이에 내용을 작성하고 저장한 뒤 **작성한 질문지 업로드**를 누릅니다.
- 일부만 작성한 파일도 불러올 수 있습니다. 빈 답변은 현재 입력을 지우지 않으며, 내용이 있는 답변만 해당 입력란에 반영합니다. 질문·번호·파일의 표시 문구는 그대로 두고 답변 부분만 수정하세요. 다른 판단의 질문지나 질문 내용이 달라진 파일은 반영하지 않습니다.
- 업로드 후 내용을 확인하고 **답변 반영 · 자료 조사 시작**을 눌러 진행합니다. 파일 업로드만으로 조사를 시작하지 않습니다. 질문지 파일은 질문과 답변이 포함된 평문이므로 저장 위치를 확인하세요.

## 첨부 자료

- 이미 저장된 사전 질문은 기존 답변과의 연결을 유지하기 위해 자동으로 번호를 바꾸거나 재작성하지 않습니다. 의미별 질문 통합은 새 사전 검토부터 적용됩니다.
- 질문 입력 전과 사전 답변 단계에서 **자료 첨부**를 사용할 수 있습니다. 한 판단에 최대 5개, 파일당 5MB, 합계 10MB까지입니다.
- 지원 형식: TXT, MD, CSV, JSON, HTML/HTM, XML, TSV, LOG, PDF, DOCX, XLSX. 텍스트는 UTF-8 또는 UTF-16을 사용합니다.
- 파일당 추출 텍스트는 최대 12,000자, 전체는 최대 36,000자입니다. 초과분은 생략 표시와 경고를 남깁니다. 각 AI에 전달하는 단계별 문맥에도 별도 길이 제한이 있어 추가 발췌될 수 있습니다. 필요한 핵심 부분이 포함되었는지 확인해 주세요.
- PDF는 앞 40쪽까지 텍스트를 추출합니다. 이미지·스캔 PDF의 OCR과 일반 이미지 첨부는 지원하지 않습니다. PDF의 그림·표 배치, Word 서식, Excel 계산·차트 전체를 분석하는 기능이 아니며 읽은 텍스트와 저장된 셀 값을 사용합니다. 암호가 있는 PDF는 해제한 사본이 필요합니다.
- PDF·DOCX·XLSX 추출에는 로컬 Python이 필요합니다. PDF는 `pypdf`, DOCX·XLSX는 Python 표준 라이브러리를 사용합니다. 확인된 개발 환경은 Python 3.14.2와 pypdf 6.19.0이며 이번 변경에서 새 패키지를 설치하지 않았습니다. 앱이 누락된 Python·라이브러리를 자동 설치하지는 않습니다. 다른 PC에서 실행할 때는 해당 환경이 필요합니다.

## Claude·ChatGPT의 3인 토론

Claude와 ChatGPT(Codex)는 각각 기회·위험·실행 가능성을 검토하는 3개 에이전트를 실행합니다. 앱이 공식 CLI를 별도 세션으로 호출하며, CLI의 내장 에이전트 기능이나 도구 호출에 의존하지 않습니다.

1. **초안:** 3개 에이전트가 같은 질문에 서로 독립적으로 답변합니다.
2. **상호 검토:** 각 에이전트가 3개의 초안을 전달받아 반론과 보완 의견을 작성합니다. 세션은 새로 시작하며 앱이 작성된 토론 내용을 문맥으로 전달합니다.
3. **최종 종합:** 별도 진행자가 초안과 상호 검토를 종합해 한 개의 최종 의견을 냅니다.

토론 단계만 정상 완료하면 Claude 7회, ChatGPT 7회 요청이 발생하고 Gemini는 API로 1회 답변합니다. JEV가 평가하는 답변은 각 AI의 최종 의견이며 개별 에이전트의 초안과 검토는 별도로 채점하지 않습니다. 중간 판정 뒤 각 AI의 독립 재검증을 1회씩 요청하므로 토론·재검증은 Claude 7+1회, ChatGPT 7+1회, Gemini 1+1회입니다. 이에 앞서 참여 AI마다 사전 조사 계획 1회, 답변을 반영한 공개 검색어 정리 1회, 실제 조사 1회가 추가됩니다. 범위 보완이 필요하면 조사 AI마다 최대 1회 더 조사합니다. JEV는 사전 자료 분류 1회와 의견 중간 평가·재평가 2회로 정상 경로에서 총 3회 호출합니다. 복합 질문을 다시 분리해야 하면 사전 JEV 재검토 1회가 추가되며, 질문 분리·중복 제거에도 LLM 호출이 발생합니다. 전체 최종 작성은 추가 1회이며 작성 실패 시 다른 사용 가능한 AI로 재시도할 수 있습니다. 보고서 내용 검사에 실패하면 작성 AI마다 최대 1회 보완 작성하므로 추가 호출과 대기 시간이 발생할 수 있습니다. 조사로 인해 구독·API·검색 사용량과 대기 시간이 늘며 제공사 할당량이 적용됩니다.

화면에서 **사전 검토·사용자 답변 → 공개 자료 조사 → AI 토론 → JEV 중간 판정 → AI 재검증 → JEV 재평가 → 최종 의견**과 토론 요청 수를 확인합니다. **판정 · 재검증 과정**을 펼치면 두 번의 JEV 판정, 기준별 점수와 보완 초점, 각 AI가 작성한 실제 보완 답변과 오류를 확인할 수 있습니다. **토론 · 평가**에서는 최초 토론의 초안·상호 검토·AI별 종합을 볼 수 있습니다. 토론 기록은 비공개 내부 추론이 아닌 작성된 답변입니다. 이전에 저장한 단일 답변 기록에는 토론 기록을 만들어 붙이지 않습니다.

사전 검토의 각 요청에는 설정한 **단계별 응답 대기 시간**을 적용합니다. 답변 반영 후 검색어 정리·실제 조사·필요 시 보완 조사에는 요청마다 설정 시간의 2배, 최대 10분을 적용합니다. 여러 단계와 출처 수집을 거치므로 전체 실행 시간은 한 요청의 제한보다 길 수 있습니다.

설정의 **단계별 응답 대기 시간**은 초안·상호 검토·종합의 각 생성 요청에도 적용됩니다. 초안 3개와 검토 3개는 각각 병렬 실행하므로 Claude·ChatGPT의 전체 대기는 선택 시간의 최대 3배(2분 선택 시 6분, 3분 선택 시 9분, 5분 선택 시 15분)에 CLI 시작·종료 시간이 더해질 수 있습니다. Gemini에는 선택 시간이 한 번 적용됩니다. 에이전트 하나라도 실패하거나 최종 종합이 실패하면 해당 AI 전체를 이번 판단에서 제외하고 남은 AI로 진행합니다. 단일 에이전트 답변으로 자동 대체하지 않습니다. 이 토론 대기 시간 뒤에 JEV 중간 판정 → 모든 응답 AI의 독립 재검증 → JEV 재평가 → 최종 작성 시간이 더해집니다. 재검증과 최종 작성 요청에도 선택한 응답 대기 시간이 각각 적용되며, 다른 AI로 재시도하면 추가 대기할 수 있습니다.

최종 답변은 실제 검색 결과 또는 원문 수집이 확인된 출처 번호만 인용할 수 있습니다. 확인 불가 출처의 수치·본문과 검증 전 보고서 요약은 토론 근거에서 제외하며, 최종 작성에서 없는 번호·제외된 번호·인용 누락을 발견하면 다른 작성 AI를 시도합니다. 이는 인용의 접근 근거를 확인하는 검사이며 모든 문장의 사실성을 자동 보장하지는 않습니다. 긴 첨부는 추출 한도 외에도 단계별 문맥 분량에 따라 일부만 전달될 수 있습니다.

## 설정과 보관

프로젝트 `.env`에 `JEV_API_KEY`와 `GEMINI_API_KEY`를 설정합니다. `run.bat`은 이 `.env` 경로를 앱에 전달하므로 새 키를 넣고 다시 실행하면 적용됩니다. 선택 변수 `JEV_MODEL=jev-latest`를 사용할 수 있습니다. 키를 Windows 사용자별 암호화 저장소로 복사하므로, 같은 Windows 사용자로 포터블 EXE를 실행할 때도 사용할 수 있습니다. 다른 PC에서는 EXE 옆 `.env`에 키를 직접 설정해야 합니다. `.env`와 실제 키는 배포 패키지에 포함하지 않습니다.

판단 기록과 설정은 `%APPDATA%/YESorNOT/decisions.json`, 암호화된 키는 `jev-key.bin`과 `gemini-key.bin`에 각각 저장합니다. 기록은 최대 100개입니다. 질문·사전 조사 계획·사전 답변·첨부에서 추출한 텍스트·공개 조사 결과와 출처·작성된 토론·JEV 평가·최종 실행안은 기록 파일에 **평문**으로 저장됩니다. 원본 파일 전체를 기록에 복사하지는 않습니다. 사전 답변 대기 중 종료한 경우 저장한 검토와 추출 텍스트로 재개할 수 있습니다. API 키 암호화와 판단 기록의 평문 저장은 별개입니다.

질문·답변·첨부에서 추출한 내용은 사전 검토와 공개 검색어 정리를 하는 참여 AI, 필요한 자료를 분류하는 JEV, 이후 근거를 공유하는 토론·평가·최종 작성 문맥으로 전송됩니다. 원문 개인 답변과 첨부 본문을 웹 도구가 열린 조사 호출에 직접 넣지 않습니다. 도구가 꺼진 단계에서 공개 주제·지역·시기·후보 범주로 일반화한 검색어를 만든 뒤 조사 호출에는 그 검색어·목적·날짜·JEV의 조사 초점을 제공합니다. 이 일반화는 모델이 수행하므로 검색어에 민감 정보가 포함되지 않는다는 절대 보장은 아닙니다. 필요한 자료만 첨부해 주세요.

수집된 의견과 JEV의 중간 점수·판정·보완 초점은 재검증 AI에, 보완 의견은 JEV에, 최초 의견·보완 의견·JEV의 두 의견 평가는 최종 작성 AI에 전달됩니다. JEV·Gemini API 키는 렌더러나 Claude/Codex CLI 프로세스에 전달하지 않습니다. 별도 API 과금으로 실행되는 Claude/Codex 인증은 거부합니다.

CLI 작업은 빈 임시 폴더에서 수행하며 셸·파일 도구·MCP·확장·훅을 격리합니다. **실제 조사 호출에서만 웹 검색·열람 도구를 허용**하고 사전 계획·검색어 정리·토론·재검증·최종 작성에서는 웹 도구를 끕니다. 프로젝트 파일을 스스로 읽게 하지 않습니다. 공개 출처의 별도 수집에서도 URL 접근 제한을 적용합니다. 취소하면 CLI 프로세스 트리를 종료하고 진행 중인 요청을 중단합니다. 이미 처리된 서비스 사용량은 취소로 되돌아가지 않을 수 있습니다.

현재 설치된 Codex CLI에서는 검색 도구 실행에 필요한 기능이 격리 설정과 호환되지 않아 자체 조사를 `RESEARCH_TOOLS_UNAVAILABLE`로 제외합니다. 실행 격리를 풀어 임의 코드를 허용하지 않으며, ChatGPT의 사전 검토·3인 토론·재검증은 다른 AI가 실제로 조사한 공유 근거를 받아 계속 진행합니다. Gemini도 실제 Google Search 실행 메타데이터가 없는 응답은 조사 근거로 인정하지 않습니다.

## 점수와 판정

- 답변 품질: 논리성30, 실행 가능성30, 위험 고려25, 질문 적합성15점.
- 각 기준은 Jev Score의 5단계(0~4)로 평가하며, `원점수 / 4 × 배점`으로 환산합니다. 원점수는 분포의 기댓값이므로 소수일 수 있습니다.
- 새 판정은 별도의 JEV Choice로 YES / NO / CONDITIONAL(조건부 권고)을 선택합니다. 품질 점수가 높아도 최종 NO일 수 있습니다. 필요한 사실이 부족하면 조건과 가정을 밝힌 실행안을 제시하며, 무조건적인 실행이나 결과를 보장하지 않습니다.
- 인증 실패·미설치·할당량 초과·타임아웃 등으로 응답하지 못한 AI는 제외하고 성공한 답변만 채점·판정합니다. 1개 또는 2개만 성공해도 YES/NO를 유지할 수 있으며 실패한 AI의 사유를 표시합니다. 의견 수집이 모두 실패하면 의견 평가용 JEV 호출 없이 중단합니다. 앞선 사전 검토에서 발생한 JEV 호출은 별개입니다.
- 신규 실행은 HOLD를 최종 결론으로 사용하지 않습니다. 모든 응답 AI가 JEV 중간 판정과 다른 AI의 의견을 독립 검토해 반론·가정·위험·실행 조건을 보완하고, JEV가 다시 평가합니다. 재검증에 실패한 AI는 제외하며 모두 실패하면 최종 의견을 만들어 내지 않고 오류로 종료합니다.
- confidence는 분포의 집중도이며 정답 확률이나 성공 확률이 아닙니다. 이전 정책의 보류 기준이 실제 적용된 과거 기록은 원래 상태로 유지하고 당시 정책을 표시합니다.
- JEV는 서술형 최종 의견을 작성하지 않습니다. 중간 판정의 보완 초점은 JEV Choice가 고른 고정 기준 라벨이며 자유서술 판단 근거가 아닙니다. 사용 가능한 작성 AI가 모든 최초 의견, 독립 재검증 답변, JEV의 두 평가를 반영해 하나의 실행안을 작성합니다. 작성 AI와 반영한 의견 수를 표시하며 JEV 평가 모델과 구분합니다.
- 개별 카드와 상단 품질 평균은 최초 수집 답변의 점수를 유지합니다. 재검증된 답변 점수는 **판정 · 재검증 과정**의 JEV 재평가에서 별도로 표시합니다.
- 최종 보고서는 **판단 / 선택 이유 / 대안 비교 / 실행 계획 / 위험과 대응 / 결론 변경 조건**을 포함합니다. 조건부 권고에는 **현재 행동 / 선행 조건과 확인 방법 / 충족 시 실행 / 미충족 시 대안**을 명시합니다. 선택 이유에는 주요 주장의 채택·기각 이유를 설명하고, 첫 행동은 별도로 표시합니다.
- 빈 구역·중복 제목·명시적인 판단 위임 등 보고서 내용 검사에 실패하면 구체적인 보완 사유를 전달해 해당 AI에 1회 재작성을 요청합니다. 다시 실패하면 다음 검증 완료 AI를 시도하고, 모두 실패하면 완성된 보고서로 표시하지 않습니다. 이 검사는 구조와 명시적 위임 표현을 검사하며 사실 검증이나 판단 품질 자체를 증명하지 않습니다. 최종 작성 뒤 별도 JEV 심사를 추가한 것은 아닙니다.
- 최종 실행안은 고득점 답변 하나를 선택해 복사하는 단계가 아닙니다. 유효한 의견이 1개뿐이면 그 답변과 JEV 평가를 반영했다고 표시합니다. 종합에 실패하면 오류를 표시하고 수집된 의견과 평가를 유지합니다. 과거 기록에 재검증이나 종합 의견을 임의로 붙이지 않습니다. 과거 HOLD 기록은 당시 판정 그대로 표시합니다.
- 재검증은 실제 공개 조사 결과·사전 답변·첨부에서 전달된 문맥을 이용한 모델 간 검토입니다. 조사 단계의 웹 도구 실행과 앱의 원문 수집을 근거로 출처 접근 상태를 표시하지만, 재검증 단계에서 다시 웹 조사를 했다는 의미는 아닙니다. 자료를 빠짐없이 찾았거나 출처의 주장이 모두 참이거나 최종 제안이 100% 정확하다고 주장하지 않습니다.

실제 응답이 없거나 평가가 실패하면 점수를 만들어 표시하지 않습니다. 브라우저로 HTML만 열면 미리보기로 동작하며 실제 호출은 비활성화됩니다. 최초 HTML 시안 원본은 `.omx/reviews/prototype/`에 보존했습니다.
